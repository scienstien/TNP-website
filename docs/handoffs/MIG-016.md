# MIG-016: Show accessible warnings for blocked student deletions

- Owner: Model 3 (assigned by the project owner on 2026-10-23 after the tables lane)
- Branch: `companies/tables` (owner asked for this work in PR #9)
- Status: VALIDATION (awaiting review; TASKS.md is updated by Model 1 this wave)

## Scope statement

Student records table only: a visible blocked-delete reason, a clearer delete
confirmation and accessible success/failure feedback. Server authorization,
transactions, foreign keys and the delete rule itself are unchanged.

## Behavior change

- Blocked delete: a student with an offer now shows "Remove the offer before
  deleting this student." as visible text under the row actions. The disabled
  Delete button references it with `aria-describedby`. The hover `title` is kept.
- Allowed delete: the confirmation now reads "Delete {name} ({roll})? This removes
  this enrollment and its placement-cycle registrations. The person record is kept
  if they have another enrollment. This cannot be undone." (matches the store:
  the person row is deleted only when no other enrollment remains). The offer-removal
  confirmation is unchanged.
- Feedback: success messages stay in `role="status"`; any rejection is now a
  `role="alert"` with the server's exact text (`error`, else the first field error),
  in the error colour. On rejection the page is not refreshed, so the record stays
  as it was. A thrown request shows "Unable to save. Check your connection and
  retry." as an alert.

## Files

- `components/students/StudentRecords.tsx` (modified): the `message` string state is
  replaced by `feedback` (`{ text, alert }`); new exported helpers
  `deleteBlockedReason(student)`, `removalConfirmation(student, offer)`,
  `sendRemoval(student, send)` and the `DeleteAction` row control. The page's
  default export and props are unchanged.
- `components/students/students.css` (modified): `.student-action-note` and the
  top-level alert colour.
- `components/students/StudentRecords.test.tsx` (added): focused coverage (below).

## Contracts

`StudentRecords` default export/props unchanged. The four new named exports are
used by the component and its test only.

## Limitations

were not exercised in a real browser or assistive technology.
