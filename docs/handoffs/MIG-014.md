# MIG-014: Reject participation payloads with any validation error

- Owner: Model 3 (assigned by the project owner on 2026-10-23 after the tables lane)
- Branch: `companies/tables` (owner asked for this work in PR #9)
- Base: `e0698fb` on top of main `aa3865f`
- Status: VALIDATION (awaiting review; TASKS.md is updated by Model 1 this wave)

## Scope statement

Fix the `setParticipation` gate in `lib/students/store.ts` and add a regression test.
No change to validation rules, authorization, transactions, UI, schema or other
operations.

## Behavior change

Before: `validateParticipation()` returns parsed `data` and a non-empty `fieldErrors`
when a request has a valid cycle/status plus an unexpected field. `mutateStudent()`
rejected only when `data` was null, so the malformed request was written.

After: `setParticipation` returns the validation `fieldErrors` whenever any field
error exists, before the transaction, so nothing is written. Valid requests behave
as before.

## Files

- `lib/students/store.ts` (modified): the participation gate also rejects when
  `fieldErrors` is non-empty.
- `lib/students/store.test.ts` (added): two tests calling the real `mutateStudent()`
  with `DATABASE_URL` forced to an unreachable address. `server-only` is mapped to
  Next's bundled no-op build inside the test, as the Lane A verification did.
  1. Valid cycle/status plus `extra` → exactly
     `{ fieldErrors: { form: "Only the placement cycle and registration status can be set." } }`,
     with no database connection attempted.
  2. A valid request still passes validation and reaches the transaction (stopped
     only by the unreachable test database).
